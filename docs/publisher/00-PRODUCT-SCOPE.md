# TeroLibrary Publisher Studio — продуктовая спецификация

Версия 1.0 · Дополнение к TeroLibrary Author

## Цель
Отдельный кабинет издательства с общей статистикой издательства, аналитикой по каждому автору и произведению, финансовыми отчётами и управлением командой. Публичная страница издательства — отдельная часть сайта, связанная с приватным кабинетом.

## Принципы
- Общий аккаунт TeroLibrary; отдельная роль/членство внутри издательства.
- Издательство видит только произведения, закреплённые за ним в модели владения/лицензии.
- Автор сохраняет доступ к собственному авторскому кабинету.
- Никаких персональных данных читателей и индивидуальной истории чтения для издательства.
- Финансовые суммы всегда показываются с валютой; нельзя суммировать разные валюты в одно число.
- Существующий дизайн TeroLibrary сохраняется.
- Существующие publisher API и модели расширять, не создавать параллельную систему.

## Состав
1. Публичная страница издательства.
2. Publisher Studio — приватный кабинет.
3. Роли сотрудников издательства.
4. Каталог произведений.
5. Список авторов и статистика каждого автора.
6. Общая аналитика издательства.
7. Финансовые отчёты.
8. Публикации и модерация.
9. Настройки и аудит доступа.

## Роли
- `owner`: полный контроль, профиль, команда, финансовые настройки.
- `manager`: управление каталогом, авторами, публикациями и аналитикой; без передачи владения.
- `member`: ограниченный доступ по назначенным возможностям.
Текущие роли `owner | manager | member` уже присутствуют в коде. Не вводить новые роли без необходимости; уточнить permission matrix.

## Вне рамок первого релиза
- автоматическое заключение юридически значимых договоров;
- реальные банковские/криптовалютные выплаты без платёжного провайдера;
- личные сообщения и чат;
- доступ к личным данным читателей.
