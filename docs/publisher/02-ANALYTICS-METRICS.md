# Аналитика издательства и статистика автора

## Общая статистика
Периоды: 7, 30, 90 дней и произвольный диапазон. Для графиков использовать одну часовую зону отчёта и явные границы периода.

### Аудитория и чтение
- уникальные читатели;
- просмотры страниц произведений;
- открытия глав;
- engaged reads — чтение, удовлетворяющее согласованному порогу активности;
- переходы chapter N → N+1;
- completion rate произведения/глав;
- возврат читателей в агрегированном виде;
- подписки, добавления в библиотеку, оценки и комментарии.

Нельзя называть простое открытие главы «прочтением», если фактическое чтение не измеряется. В интерфейсе дать определения метрик.

### Каталог
Рейтинг и количество оценок, динамика чтений, топ произведений, конверсия между главами, доля новых/возвращающихся читателей, продажи, валовая выручка, комиссия и начисленные роялти.

### Финансы
Количество оплаченных продаж, валовая выручка, комиссии, роялти авторам, начислено/выплачено/к выплате, разбивка по валютам, возвраты отдельно при наличии источника данных.
Не складывать EUR, RSD, USD и другие валюты в единый итог без явной конвертации по сохранённому курсу и дате.

## Статистика автора внутри издательства
- агрегат по произведениям, закреплённым за издательством;
- список произведений и сравнение;
- читатели/чтения/просмотры;
- воронка глава-за-главой;
- дочитывания и точки оттока;
- подписчики, оценки и комментарии;
- продажи и роялти по валютам;
- динамика по времени.

Авторская статистика издательства не включает самостоятельные произведения автора, не связанные с данным издательством. Если произведение лицензировано нескольким сторонам, правила атрибуции фиксируются в договоре/лицензии и аналитической модели.

## Приватность
- Не показывать имена, email, IP, точную геолокацию или индивидуальную историю чтения пользователей.
- Не давать издательству выгрузку списка читателей.
- Демографические разрезы — только если законно собраны, разрешены политикой конфиденциальности и агрегированы.
- Вводить порог минимальной выборки для срезов, чтобы нельзя было вычислить отдельного читателя.
- CSV содержит только агрегаты и финансовые записи, на которые у роли есть разрешение.

## Источник данных
Текущий проект уже содержит `publisherReport()` по продажам/выручке/комиссиям/роялти и `publisherWorks()` с продажами по произведениям. Для читательской аналитики нужно проверить существующие event tables и `getAuthorStats()`. Не строить новые метрики до аудита событий, чтобы не показывать вымышленные цифры.
