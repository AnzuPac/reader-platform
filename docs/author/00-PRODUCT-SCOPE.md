# TeroLibrary Author — продуктовая спецификация

Версия 1.0 · Приоритет: авторы · Издательства вне объёма текущего этапа

## Цель
Сделать авторскую мастерскую, в которой пользователь может вести собственные произведения от рукописи до публикации, работать с файлами из других редакторов, анализировать чтение и продолжать писать на телефоне. Это развитие существующего кабинета автора, а не отдельная система аккаунтов.

## Принципы
1. Один аккаунт TeroLibrary для сайта, читалки и Author.
2. Автор может вести несколько произведений и псевдонимов в рамках одной учётной записи.
3. Самиздат — единственный сценарий владения/публикации в текущем релизном объёме.
4. Не менять существующие права на книги и ограничения экспорта.
5. Не удалять и не перезаписывать рукопись автоматически.
6. Автосохранение и история изменений важнее декоративных функций.
7. Интерфейс остаётся в визуальном языке TeroLibrary: существующая палитра, шрифты, компоненты, скругления и навигация.
8. Мобильное приложение автора — отдельное приложение от reader, но использует общий backend.

## Входит в текущий этап
- авторский профиль и настройки;
- обзор/дашборд;
- библиотека произведений и создание/редактирование карточки;
- редактор глав и управление структурой;
- черновики, расписание, публикация;
- безопасные правки опубликованных глав;
- импорт, экспорт, файловые операции и резервная копия;
- статистика, комментарии и уведомления;
- мобильный Author: офлайн-черновики, синхронизация и обмен файлами;
- доступность, локализация, аудит безопасности и тесты.

## Не входит сейчас
- кабинеты издательств и их рабочие процессы;
- заявки в издательства, контракты, комиссии, выплаты издательствам;
- совместная редактура издательства;
- корпоративные роли publisher/editor/manager.
Архитектурные точки расширения допустимы, но не создавать сейчас неиспользуемые пользовательские экраны и API издательств.

## Главные пользовательские сценарии
A. Новый автор: активировать авторский статус → заполнить профиль → создать произведение → добавить главы → сохранить черновик → опубликовать.
B. Автор с готовой рукописью: импортировать файл → просмотреть структуру и предупреждения → сопоставить главы → подтвердить → продолжить редактирование.
C. Автор правит опубликованную главу: создать новую редакцию → увидеть разницу → отправить на проверку → получить решение → опубликованная версия меняется только после разрешённого одобрения.
D. Автор пишет без сети: локально сохраняет изменения → видит очередь синхронизации → при конфликте получает обе версии и ручное разрешение.
E. Автор забирает работу: выбирает всё произведение/главы/формат → сервер проверяет право экспорта → формирует файл → отдаёт временную приватную ссылку.

## Метрики качества
- нет потери текста при навигации, закрытии вкладки или временном отсутствии сети;
- все опасные операции имеют подтверждение и восстановление;
- импорт показывает структуру до записи в библиотеку;
- экспорт воспроизводим и не нарушает права доступа;
- основные действия доступны с телефона одной рукой;
- экран редактора не перегружен панелями;
- тесты проверяют ownership, права, конфликты синхронизации и повреждённые файлы.
