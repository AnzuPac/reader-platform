# Редактор, сохранение, версии и офлайн-синхронизация

## Текущая точка
В архиве уже есть `components/ChapterEditor.tsx`, TipTap и API `/api/author/chapter`, `/api/author/publish`, `/api/author/chapter-edit`. В компоненте уже встречаются импорт в текущий редактор, вставка изображения, открытие главы и отправка правки опубликованной главы. Развивать этот редактор, не создавать параллельный редактор.

## Модель документа
- TipTap/ProseMirror JSON — предпочтительный канонический формат, если текущая БД хранит HTML, переход выполнять постепенно с обратной совместимостью.
- HTML остаётся форматом рендеринга/совместимости.
- Каждая версия документа содержит `revision_id`, `chapter_id`, `author_id`, `content`, `content_hash`, `word_count`, `created_at`, `source` (web/mobile/import/restore).
- Версия неизменяема после создания.

## Автосохранение
Состояния: `clean`, `dirty`, `saving`, `saved`, `offline_pending`, `conflict`, `error`.
- debounce на вводе; сохранять также при blur/смене главы;
- индикатор статуса всегда видим;
- сервер принимает `baseRevision`/ETag;
- если база уже новее, возвращать `409 revision_conflict`, не перетирать;
- повтор запроса с тем же idempotency key не создаёт дубликат;
- локальная очередь сохраняет неотправленные операции;
- перед уходом при незавершённой отправке показать предупреждение.

## История версий
- автоматические версии по значимым сохранениям и перед публикацией;
- ручная точка восстановления;
- список с датой, источником, автором устройства, количеством слов;
- preview и diff;
- восстановление создаёт новую версию на основе выбранной, а не удаляет последующие версии.

## Опубликованные главы
- опубликованный контент не меняется прямым обновлением из редактора;
- новая редакция хранится отдельно;
- автор видит diff;
- заявка на изменение содержит базовую опубликованную ревизию;
- при одобрении применять только если базовая ревизия всё ещё актуальна;
- при отклонении сохранять текст и комментарий модератора;
- текущий `chapter_edit_requests` сохранить и мигрировать, а не заменить без необходимости.

## Офлайн-режим
- локальное хранилище черновиков с шифрованием на уровне платформы, если поддерживается;
- офлайн доступен для собственных черновиков, не для защищённого платного контента;
- синхронизация при восстановлении сети и при явном действии пользователя;
- прогресс каждой операции: ожидает, отправляется, синхронизировано, ошибка;
- конфликт не решать правилом last-write-wins;
- при конфликте сохранить локальную и серверную версии, показать сравнение и дать выбрать/объединить;
- после подтверждения объединения создаётся новая ревизия.

## UX редактора
- простой/расширенный режим — один редактор и разные уровни панели;
- расширенный: структура, заметки, версии, поиск;
- простой: текст, базовое форматирование, слова, сохранение;
- режим без отвлечений;
- горячие клавиши на десктопе;
- удобная клавиатура и большие hit-area на телефоне;
- подтверждение удаления главы и предупреждение перед публикацией.
