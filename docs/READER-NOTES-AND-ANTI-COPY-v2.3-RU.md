# TeroLibrary — заметки, запрет копирования и режимы графического чтения v2.3

## 1. Android: защита от скриншотов

В `MainActivity.prepareSystemBars()` уже используется `WindowManager.LayoutParams.FLAG_SECURE`. Не удалять и не ослаблять этот флаг: он запрещает стандартные системные скриншоты и запись экрана на поддерживаемых версиях Android.

## 2. Android: выделение только для заметок

- Текст главы остаётся выделяемым, потому что заметки привязаны к диапазону символов.
- Системное контекстное меню WebView с Copy/Cut/Share не показывается через `setCustomSelectionActionModeCallback`.
- После выделения текста читатель видит только действие добавления заметки (и закрытие панели).
- Не добавлять действие «Выделить» без заметки.
- Не отключать само выделение: иначе заметки по фрагменту текста перестанут работать.

## 3. Сайт: запрет копирования текста глав

На контейнере текста главы отключены события `copy`, `cut`, `contextmenu`, `dragstart`. CSS сохраняет `user-select: text`, чтобы пользователь мог выбрать фрагмент и создать заметку. Правило применяется и к бесплатным, и к платным главам в читательском интерфейсе. Редактор автора не затрагивается.

Это клиентское препятствие, а не абсолютная DRM-защита. Текст, который браузер получил для отображения, технически можно извлечь через DevTools, сетевые запросы, расширения, OCR или внешнюю съёмку экрана. Не обещать невозможность копирования.

## 4. Графическая литература: режимы чтения

В `ComicReader` доступны:
- `Вебтун / Webtoon` — вертикальная непрерывная лента страниц;
- `По страницам / Pages` — одна страница на экране;
- направление перелистывания `Слева направо / Left to right`;
- направление перелистывания `Справа налево / Right to left`.

В режиме страниц направление влияет на свайпы, стрелки клавиатуры и кнопки предыдущей/следующей страницы. Выбор режима и направления сохраняется локально на устройстве. Существующие масштабирование, pinch-to-zoom, двойное касание, ширина страницы, доступ к страницам и покупка закрытой главы сохраняются.

Фильтр направления в каталоге (`gdir`) остаётся метаданными произведения и не подменяет пользовательскую настройку перелистывания в ридере.

## 5. Что уже есть в серверной защите текста и что требует доработки

В исходном `app/api/chapter/text/route.ts` уже есть проверка `chapterGate`, заголовок `Cache-Control: no-store, private`, лимит 60 запросов текста в минуту, ограничение до 3 устройств для платного контента и персональный водяной знак по user_id. Это полезные меры, их нужно сохранить.

**Обнаруженный риск графической литературы:** `app/api/author/pages/route.ts` сохраняет страницы комиксов в `public/uploads/comics/...`, а `app/api/pages/route.ts` после проверки доступа возвращает прямые `file_path`. Поскольку файлы находятся в публичной папке Next.js, прямой URL может обходить проверку `chapterGate`. До публикации платной графической литературы это нужно исправить: переносить страницы в приватное хранилище, выдавать их через защищённый media endpoint с проверкой доступа, короткоживущими токенами и `no-store`. Нужна миграция уже загруженных файлов из `public/uploads`; просто скрыть URL в UI недостаточно.

UI-блокировки не заменяют серверную защиту. Для усиления защиты в production следует отдельно внедрить и проверить:
- авторизованный endpoint выдачи текста/страниц с проверкой права на каждую главу;
- короткоживущие подписанные URL/токены для медиа, без постоянных публичных адресов файлов;
- потоковую выдачу фрагментами и ограничения частоты/объёма запросов;
- приватное хранилище для графических страниц вместо `public/uploads`, защищённый media endpoint и миграцию существующих файлов;
- персонализированный видимый или forensic-watermark (пользователь/заказ/время) для платных материалов, с минимизацией персональных данных;
- аудит аномальной загрузки глав, лимиты устройств и rate limiting;
- запрет индексации закрытых глав и проверку кэширования/CDN;
- контроль доступа к исходным файлам в хранилище и резервным копиям.

Шифрование на диске защищает хранилище, но само по себе не мешает пользователю скопировать уже расшифрованный текст из браузера. Полностью исключить пиратство на обычном веб-сайте невозможно; цель — снизить массовое копирование, облегчить обнаружение утечек и защитить права законных пользователей и авторов.

## 6. Регрессионные проверки перед релизом

- Android FLAG_SECURE остаётся включённым.
- Android: выделить фрагмент → нет системных Copy/Cut/Share → добавить заметку → заметка сохраняется и восстанавливается.
- Сайт: выделить фрагмент → добавить заметку; Ctrl/Cmd+C, контекстное меню и перетаскивание не копируют текст через стандартные действия браузера.
- Проверить, что комментарии к абзацам, перевод и транслитерация не сломаны.
- ComicReader: Webtoon показывает все страницы вертикально; Pages показывает одну страницу; LTR/RTL корректно меняет свайп/стрелки/кнопки; настройки сохраняются после перезагрузки.
- Покупка/доступ к закрытой главе и API-проверка прав не меняются.
