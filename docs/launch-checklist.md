# Чек-лист запуска

Документ для вывода читалки из демо в публичный запуск. Отмечать по мере выполнения;
всё, что помечено «проверить на сервере», проверяется на боевой машине, не локально.

## 1. Переменные окружения

Скопировать `.env.example` → `.env`, заполнить:

| Переменная | Что это | Обязательно |
|---|---|---|
| `SITE_URL` | канонический адрес сайта, `https://…` | да |
| `JWT_SECRET` | случайная строка ≥32 символов, только для сессий | да |
| `ADMIN_TOKEN` | ключ админки, длинный случайный | да |
| `DATABASE_URL` | PostgreSQL; без него локальный SQLite | для прода |
| `STRIPE_SECRET_KEY` | ключ Stripe (тест/бой) | для карт |
| `STRIPE_WEBHOOK_SECRET` | подпись вебхука | для карт |
| `STRIPE_PRICE_READER`, `STRIPE_PRICE_READER_PLUS` | id цен подписки | для подписки |
| `OLLAMA_URL` | локальная модель для переводов | опционально |
| `TRANSLATE_MODEL` | модель, по умолчанию `qwen2.5:7b` | опционально |
| `DONATION_FEE_PCT` | доля площадки с донатов, по умолчанию 10 | опционально |
| `SQLITE_DIR` | папка SQLite, если без Postgres | опционально |

Проверки:

- [ ] `JWT_SECRET` и `ADMIN_TOKEN` сгенерированы (`openssl rand -base64 48`), не дефолтные.
- [ ] `.env` не в git (`git check-ignore .env`).
- [ ] `SITE_URL` совпадает с фактическим доменом (sitemap/robots/редиректы).
- [ ] Секреты Stripe — боевые, вебхук указывает на `https://<домен>/api/webhooks/stripe`.

## 2. Домен, HTTPS, сервер

- [ ] A/AAAA-запись домена на сервер; DNS проверен (`dig`).
- [ ] HTTPS-сертификат (Let's Encrypt/Caddy/Cloudflare), продление автоматическое.
- [ ] HTTP → HTTPS редирект.
- [ ] Порт приложения (3020) не открыт наружу, только через reverse proxy.
- [ ] `X-Forwarded-Proto`/`Host` прокинуты прокси.
- [ ] Заголовки безопасности: HSTS, `X-Content-Type-Options`, `Referrer-Policy`.
- [ ] Лимит размера загрузок на прокси согласован с приложением.
- [ ] Часовой пояс сервера и даты в отчётах проверены.

## 3. База и бэкапы

- [ ] PostgreSQL 16 (или SQLite на одном инстансе), схема применена при старте.
- [ ] `scripts/backup.sh` запускается вручную и по cron (например `15 3 * * *`).
- [ ] `BACKUP_DIR` на отдельном диске/в объектном хранилище, не на том же томе.
- [ ] `KEEP` (по умолчанию 14) устраивает; старые копии удаляются.
- [ ] Проверено восстановление из дампа на чистой БД (не только создание копии).
- [ ] Отдельно бэкапятся `public/uploads` и `data/storage` (обложки, страницы комиксов).
- [ ] Мониторинг свободного места и размера БД.

## 4. Health-check и мониторинг

- [ ] `GET /api/health` возвращает `{ok:true, db:"up"}` и 200.
- [ ] Внешний uptime-монитор на `/api/health` каждые 1–5 минут, алерт на 503.
- [ ] Алерты: 5xx, рост 429, ошибки БД, кончилось место, сертификат <14 дней.
- [ ] Логи приложения собираются и не содержат токенов/паролей/текстов глав.
- [ ] Проверен smoke после рестарта: главная, каталог, книга, комикс, кабинеты.

## 5. Docker / процесс

- [ ] `docker compose up -d --build` поднимает `db` и `app`.
- [ ] `restart: unless-stopped` у обоих сервисов.
- [ ] Пароль Postgres в compose заменён на боевой (не `change-me`).
- [ ] Тома `pgdata`, `uploads`, `storage` на постоянном диске.
- [ ] `docker compose exec app node -e "fetch('http://127.0.0.1:3020/api/health')…"` — ок.
- [ ] Обновление: сборка нового образа, миграции при старте, откат на прошлый тег.
- [ ] Лимиты ресурсов (память/CPU) заданы, если на сервере несколько сервисов.

## 6. Юридическое (Сербия)

- [ ] Юрлицо: d.o.o. зарегистрировано, уставная деятельность подходит под продажу
      цифрового контента и выплаты авторам/издателям.
- [ ] PDV: проверен порог обязательной регистрации и режим для цифровых услуг;
      счета и фискализация согласованы с бухгалтером.
- [ ] Договор с издателем: комиссия, роялти, отчётный период, выплаты, возвраты,
      ответственность за права на контент, порядок расторжения.
- [ ] Оферта/условия для читателей: доступ после покупки, возвраты, подписка,
      правила донатов и модерации.
- [ ] Политика конфиденциальности и обработка ПДн: какие данные, сроки хранения,
      удаление аккаунта, логи устройств/водяные знаки — отражено честно.
- [ ] ZZPL (закон о защите прав потребителей): дистанционная продажа, право на
      отказ для цифрового контента, понятные цены и валюта.
- [ ] Налоговый учёт донатов авторам и выплат: статус, документы, отчётность.
- [ ] Проверены требования к хранению данных и возрасту (0/16/18+).

## 7. Что включить перед публичным запуском

- [ ] Stripe live: ключи, вебхук, тестовая покупка и возврат на боевом домене.
- [ ] Ручной режим оплаты оставить как резерв и описать издателю.
- [ ] Лимиты запросов (`lib/ratelimit.ts`) и лимит устройств проверить под нагрузкой.
- [ ] Защита платного контента: `no-store`, водяной знак, запрет копирования — на
      боевых страницах.
- [ ] Мониторинг и алерты (см. п. 4), дежурный контакт.
- [ ] Резервный план при падении: статическая заглушка/второй инстанс, DNS-переключение.
- [ ] Демо-данные не попали в прод: `demo.*@example.com` отсутствуют.
- [ ] Админ-токен выдан ограниченному кругу, хранится в менеджере секретов.
- [ ] Прогон сценария из `docs/demo-scenario.md` на боевой сборке.
- [ ] Поддержка: почта/форма, время ответа, обработка жалоб на контент.

## 8. Финальная приёмка

```bash
npm run check                 # тесты + сборка
npm run seed:demo             # на чистой БД и на существующей — без дублей
bash scripts/backup.sh        # копия создаётся
curl -fsS https://<домен>/api/health
```

- [ ] `npm run check` — exit 0, тестов не меньше 70.
- [ ] 200 на `/sr`, `/sr/catalog`, `/sr/work/<slug>`, `/sr/read/<id>`, `/sr/publisher`,
      `/sr/publishers`, `/sr/admin/publishers`.
- [ ] Покупка книги, донат, покупка главы комикса — смоук пройден.
