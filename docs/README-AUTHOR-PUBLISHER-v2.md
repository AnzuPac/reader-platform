# TeroLibrary — полный комплект Author Studio + Publisher Studio

**Актуальная согласованная версия: 2.0 · 26.11.2026**

Этот архив объединяет исходный проект TeroLibrary, единое ТЗ, инструкции разработчику, аудит текущей реализации и демонстрационный интерфейс.

## С чего начать
1. Прочитать `TeroLibrary-web/docs/PRODUCT-SCOPE-v2.md`.
2. Прочитать `TeroLibrary-web/docs/DESIGN-SYSTEM-AUTHOR-PUBLISHER.md` — это утверждённый дизайн.
3. Свериться с `TeroLibrary-web/docs/IMPLEMENTATION-STATUS.md`, чтобы отличать готовое от запланированного.
4. Изучить `docs/author/` и `docs/publisher/`.
5. Открыть `docs/author/author-workspace-preview.html` в браузере для просмотра макета Author Studio.

## Состав
- `TeroLibrary-web/` — исходный проект + документация.
- `TeroLibrary-Android/` — Android reader из исходного архива.
- `docs/author/` — ТЗ авторской среды, навигация, редактор/синхронизация, импорт/экспорт, API/данные, QA и макет.
- `docs/publisher/` — ТЗ внутреннего кабинета издательства, навигация, аналитика, доступы, API/данные, приёмка.
- `docs/DESIGN-SYSTEM-AUTHOR-PUBLISHER.md` — визуальный стандарт для Author и Publisher.
- `docs/IMPLEMENTATION-STATUS.md` — статический аудит исходника.
- `docs/PRODUCT-SCOPE-v2.md` — единая актуальная спецификация.

## Зафиксированные решения
- Author и Publisher — разделы TeroLibrary с общим аккаунтом и backend.
- Publisher Studio — приватный кабинет, **без публичной страницы издательства и без отдельного сайта**.
- Внутренний каталог издательства отделён от публикации в общий каталог.
- Статистика издательства включает только относящиеся к нему произведения, а не все работы автора.
- Аналитика читателей — агрегированная и без персональных данных.
- Финансы разделяются по валютам.
- Авторская среда использует существующий TipTap editor как основу.
- Целевой дизайн — актуальная светлая нейтральная тема TeroLibrary/slate с категорийными акцентами, не бежевая/коричневая тема.

## Важно
HTML-макет — демонстрационный прототип с условными данными и локальной интерактивностью. Он не подключён к backend. Архив не означает, что весь описанный функционал уже реализован. Все изменения должны проходить аудит, миграции и QA.
